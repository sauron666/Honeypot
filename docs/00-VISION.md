# 00 — Визия, потребители и конкурентен анализ

## 1. Проблемът

Средното време за откриване на пробив (dwell time) в EU mid-market е седмици.
Причината не е липса на логове — а че **всичко в реалната мрежа е шумно**.
EDR/SIEM гледат легитимна инфраструктура, където атакуващият се крие сред 10 млн.
нормални събития на ден.

Deception обръща логиката: слагаш в мрежата обекти, които **нямат легитимна причина
да бъдат докоснати**. Всяко докосване = сигнал с ~0% false positive.

Проблемът с днешните deception продукти:

1. **Разпознаваеми са.** Емулирани услуги се фингърпринтват (timing, липсващи
   команди, дефолтни ключове, празен диск, uptime 3 дни, нула user activity).
   Сериозен оператор ги подушва за минути и просто ги заобикаля.
2. **Плитка форензика.** Получаваш "SMB login на decoy" — не получаваш филм на
   пробива: какви инструменти, какъв C2, какви креденшъли, каква следваща стъпка.
3. **Затворени.** Скъпи, вендор-заключени, лоша интеграция с open SOC stack.
4. **Статични lures.** Breadcrumbs остаряват, никой не ги обновява, покритието е
   неизмеримо.

## 2. Продуктовата теза

> **Не откривай атаката. Наеми атакуващия да ти я демонстрира.**

MIRAGE прави примамките неразличими от реални системи (защото **са** реални системи),
наблюдава ги от хипервайзора (където атакуващият няма достъп), и превръща всяка
сесия в готова детекция за реалната мрежа.

Три стълба:

| Стълб | Твърдение |
|---|---|
| **Undetectable** | Няма in-guest агент. Няма емулация там, където има значение. Няма два еднакви deploy-а. |
| **Total recall** | PCAP + syscall + файл + registry + keystroke + екран + памет. Всичко, с hash chain. |
| **Actionable** | Изходът е Sigma/YARA/Suricata/STIX за реалния SOC, не поредният дашборд. |

## 3. Потребители

| Персона | Болка | Какво получава |
|---|---|---|
| SOC analyst (L1/L2) | 300 alert/ден, 99% шум | 2 alert/ден с 100% сигурност + пълен timeline |
| IR / DFIR | липсва telemetry след факта | пълен запис, memory dump, sample, chain of custody |
| Threat hunter | няма локален TI | реални TTP от собствената мрежа → Sigma правила |
| Blue team lead / CISO | не може да докаже detection capability | Deception Coverage Score, NIS2/ISO27001 доказателства |
| MSSP | иска multi-tenant, ниски разходи | един контролер, N тенанта, per-decoy pricing |
| OT/ICS оператор | не може да сложи агент на PLC | пасивни ICS примамки (Modbus/S7/DNP3) + мрежов запис |

## 4. Конкурентен анализ (детайлно)

### Fortinet FortiDeceptor
- Силно: интеграция с FortiGate/FortiSIEM, ICS decoys, лесен deploy (appliance).
- Слабо: decoys са контейнерни/емулирани VM образи с ограничен реализъм; форензиката
  е на ниво event; няма hypervisor introspection; няма ransomware key capture;
  заключен в Fortinet Security Fabric; лицензът е per-VM и скъп.
- **Как го бием:** истински OS + VMI + пълна session forensics + отворени интеграции.

### SentinelOne Singularity Identity (ex-Attivo)
- Силно: identity deception в AD е най-доброто на пазара, in-memory lures на endpoint.
- Слабо: изисква S1 агент навсякъде; мрежовите decoys са слаби; няма дълбока
  форензика на самата примамка.
- **Как го бием:** покриваме identity частта (kerberoast/AS-REP/DCSync/ESC1 капани,
  генерирани от реалната AD схема) **и** мрежовата, без да изискваме конкретен EDR.

### Acalvio ShadowPlex
- Силно: "distributed deception" — projection на много IP-та от малко ресурси, добър
  autopilot за разполагане.
- Слабо: предимно ниско/средно взаимодействие; cloud-first; непрозрачно.
- **Как го бием:** същият projection модел (`mirage-honeyd`) **плюс** високо
  взаимодействие там, където атакуващият задълбава.

### Thinkst Canary / Canarytokens
- Силно: брилянтна простота, нулев false positive, най-добрият UX на пазара.
- Слабо: съзнателно ниско взаимодействие — казва ти "нещо се случи", не "какво".
- **Как го бием:** не се бием — вземаме UX-а им за tokens (`mirage-tokens`) и
  добавяме дълбочината, която те принципно отказват да правят.

### Open source (T-Pot, Cowrie, OpenCanary, DejaVu, HoneyTrap)
- Силно: безплатно, гъвкаво.
- Слабо: фингърпринтваеми (Cowrie има публични сигнатури), без централен контрол,
  без containment гаранции, без форензична цялост, без продуктов UX.
- **Как го бием:** те са компоненти, ние сме платформа. Ще ги поддържаме като
  опционални drivers, но с наш orchestration, containment и forensics слой.

## 5. Дизайн принципи (не се нарушават)

1. **Containment преди функционалност.** Примамка, която може да атакува навън, е
   юридически и морален провал. Всеки нов feature минава през `docs/04`.
2. **Agentless в примамката.** Ако нещо трябва да работи вътре в decoy-а, търси
   начин да го направиш от хипервайзора.
3. **Никакво поведение по подразбиране, което може да се сигнатурира.**
   Всеки deploy рандомизира артефакти, ключове, банери, имена, timing.
4. **Append-only истина.** Събитие веднъж записано не се променя. Hash chain.
5. **Изходът е детекция, не дашборд.** Всяка сесия трябва да произведе нещо, което
   реалният SOC може да зареди.
6. **Без hack-back. Без offensive.** Наблюдаваме, задържаме, документираме. Точка.
