# 07 — Overlay режим (presence)

Понякога не можеш да пипаш мрежата на клиента — няма VLAN за deception, няма
достъп до суича. Overlay режимът проектира декои в чужд сегмент през тунел, без
да променя нищо в мрежата.

Архитектура: **Presence Hub** (при директора) + **Presence Agent** (в целевия
сегмент). Агентът вдига локални listener-и, които изглеждат като хостове там, и
мултиплексира трафика през mutual-TLS тунел към хъба, където живее реалната
измама.

## Сигурност на тунела

- **Взаимен TLS със собствен CA** (`internal/presence/ca.go`) — нито хъбът, нито
  агентът приемат непознат сертификат.
- **TLS ръкостискането е явно** в `serveAgent` — ако оставиш на първия `Read`,
  проблем със сертификат излиза като „връзката не започна с hello" и праща
  човека в грешна посока.
- **Fail-closed**: ако тунелът падне, агентът затваря listener-ите. По-добре
  никаква примамка, отколкото примамка без запис.

## Издай PKI материала

```bash
./bin/miragectl presence-ca \
  -agents branch-sofia,branch-varna \
  -hosts hub.example.com,203.0.113.10 \
  -dir presence-pki -days 730
```

Това създава CA, hub сертификат и по един сертификат на агент. Раздай на всеки
агент неговия комплект; хъбът пази своя.

## Пусни хъба и агента

Хъбът се вдига от директора (конфигуриран в манифеста). Агентът е отделен бинар:

```bash
./bin/mirage-presence -config agent-sofia.yaml
```

## Наблюдение от конзолата (GUI)

Секция **Presence** показва свързаните агенти, адресите и тунелите. Секция
**Topology** ги рисува като клони от хъба.

## Инженерните капани (вече платени)

- Мултиплексорът не блокира read цикъла — доставката минава през буфериран
  канал; при препълване потокът се затваря, не блокира тунела.
- Затварянето на поток не изхвърля вече пристигнали данни.
- `streamConn` спазва read deadline-ите — иначе тунелирана сесия виси, докато
  атакуващият държи сокета.
- `Agent.Close()` не чака backoff-а — спирането е под секунда, не цял
  `reconnect_max`.

Всичко това има тестове; изброено е в CLAUDE.md „капани".
