# 09 — Breadcrumbs

Декой без път до него е безполезен. Breadcrumbs подхвърля **следи на реални
машини** — .rdp файлове, `~/.aws/credentials`, ssh config, bash история — които
водят атакуващия към honeynet-а. Всяка следа носи регистриран honeytoken, така
че самото ѝ използване е сигнал.

Бинар: `mirage-breadcrumbs`.

## Инвариантът: пише на чужда машина, затова не разрушава

Breadcrumbs работи на **реален** endpoint (лаптоп на служител, jump host). Значи
не бива да чупи нищо:

- **Никога не презаписва съществуващ файл** — `O_EXCL` за нови файлове, fenced
  append за съществуващи (ясно ограден блок).
- **Всеки crumb носи регистриран honeytoken**, не истинска тайна.
- **Манифест пази какво е поставено**, за да се махне точно то.
- `Remove` възстановява реалния файл **байт-за-байт**.

Тестовете доказват append+remove round-trip и rollback.

## Постави следи

```bash
# покажи какво би поставил, без да пипаш нищо
./bin/mirage-breadcrumbs plan --config crumbs.yaml

# постави следите; издава honeytokens от директора и записва
# манифест на точно каквото е поставено
./bin/mirage-breadcrumbs apply --config crumbs.yaml --manifest out.json

# махни ги чисто (възстановява оригиналите байт-за-байт по манифеста)
./bin/mirage-breadcrumbs remove --manifest out.json
```

Конфигът (`crumbs.yaml`) сочи към директора (за да минтне токените), таргет ОС/
home/потребител и списък декои с host/service. С `--offline` работи и без
директор.

Типични следи:

- `~/.aws/credentials` с honeytoken AWS ключ → всяко използване гърми.
- `.rdp` файл към „jump-01" (всъщност декой).
- ssh config запис за „backup-nas".
- bash история с ред „mysql -h db01 -u dba -p…".

## Как се връзва в разказа

Атакуващият превзема реалния лаптоп → намира следата → тръгва към декоя →
honeytoken-ът гърми и engagement-ът започва. Ти виждаш целия път: от кой реален
хост, по коя следа, до кой декой.

## Комбинирай с overlay

В [overlay режим](07-overlay-mode.md) следите сочат към агентовите listener-и в
сегмента, а измамата живее при хъба. Атакуващият не вижда тунела.
